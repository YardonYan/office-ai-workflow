# 第三步 · 理流程 → 一张图

图不是装饰。它的作用是让人一眼看出「谁在等谁」。

## 什么时候用

推进总卡在某一步，或者要跟别人解释一件多环节的事。文字描述三遍不如一张图。

## 输入

| 字段 | 必填 | 默认 | 什么算坏输入 |
|---|---|---|---|
| `{流程}` | 是 | — | 只有「大概是这样」，说明现状本身没摸清 |
| `{图的目的}` | 是 | 讲顺序 | 讲顺序用流程图，讲分工用职责图，两者别混 |
| `{现有材料}` | 否 | 无 | 旧流程图可以给，但要说清是否还准确 |

## 提示词

```
把「{流程}」整理成一张图，用途是 {图的目的}。

要求：
1. 先列出所有动作，标出哪些能并行、哪些必须串行。并行的不要画成先后。
2. 标出人工审核节点。凡是对外输出、涉及花钱、涉及权限的，前面必须有人确认。
3. 标出交接点：谁交给谁、交什么、什么时候交。
4. 角色写到岗位，不要写「团队」「相关同事」。

先给我文字版的节点清单让我确认，确认后再出 Mermaid 代码。
不要一上来就画图。
```

## 输出契约

- 节点清单（文字）+ Mermaid 代码两段
- 每个审核节点有明确的前置条件
- 并行分支用并行结构，不是顺序箭头

## 验收

- [ ] 并行的事没被画成先后
- [ ] 每个对外输出前面有人工审核
- [ ] 责任人是岗位，不是「团队」
- [ ] 箭头上的动作是动词，不是「处理」「跟进」

## 失败处理

流程本身没人说得清，就先画现状图，把不确定的地方标成「此处待确认」。不要设计一个理想流程然后当成现状。

## 常见错误

| 错误 | 后果 | 改法 |
|---|---|---|
| 全是方框没有判断 | 执行时走错分支 | 有条件的地方用菱形，写清判据 |
| 漏掉审核节点 | 错误直接对外 | 对外、花钱、动权限一律前置审核 |
| 层级混乱 | 图和说明对不上 | 先定三层：阶段、步骤、动作 |
| 一张图塞太多 | 汇报时看不清 | 主图不超过七个节点，细节拆子图 |
