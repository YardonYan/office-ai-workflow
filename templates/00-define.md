# 第 0 步 · 定义 → 任务卡

动手之前先把四件事写下来。这一步省掉的十分钟，后面要还两小时。

## 什么时候用

每次开一个新任务都用。熟悉之后不用写全，但四问要在脑子里过一遍。

## 提示词

```
我有一件活要交给你做，先帮我把边界定义清楚，不要直接开始做。

我的初步想法：{用一两句话说你想做什么}

请按四问帮我补齐，缺的标「待定」并告诉我可以向谁确认：

1. 要解决什么：这次任务的目的是什么，做完给谁看、用来做什么决定
2. 重点看什么：最关心的两到三个点，其余可以粗
3. 输出成什么：交付物的形态（表格、大纲、简报、图）、大概篇幅
4. 按什么标准验收：什么情况下算合格，什么情况下必须退回

补完之后，用一段话复述成任务卡，等我确认。
```

## 任务卡长什么样

```
【目标】完成 10 月部门复盘，供周会用，支撑下月排期决策
【重点】客户反馈、进度卡点
【产出】一页简报 + 行动清单 + 统计表 + 五页大纲
【标准】数字有出处；负责人不臆造；问题页必须带措施
【不做】不涉及预算调整；不评价个人绩效
```

最后一行「不做」最容易被忽略。写清不做什么，比写做什么更能防止跑偏。

## 资料交出去之前自查

| 查什么 | 具体 |
|---|---|
| 命名 | 文件名能看出是什么，不要 `新建文档(3).docx` |
| 时间 | 所有文件的时间范围一致，跨月的要标清 |
| 口径 | 同一指标在各文件里定义一致 |
| 脱敏 | 客户名称、报价、身份证号、内部代号已处理 |

四样里有一项不过关，先处理，别急着开工。

## 验收

- [ ] 四问都有答案，或明确标注「待定」
- [ ] 有一句「不做什么」
- [ ] 交付物形态具体到能想象出样子
- [ ] 验收标准能判断是或否

## 失败处理

四问里有两问以上答不上来，说明这件事还不该开始。停下来先问清楚，不要边做边猜。

## 一句话

任务描述模糊，是结果不稳定的第一原因。比换模型、调提示词都管用的一招，是把这四件事写下来。
