# 完整走查

这一册放**做出来的演示**，不是真实案例。

和 `04-real/` 的区别，一句话：那里放「谁在什么时候写的、结果如何」，这里放「按七步走一遍，每步的产物长什么样」。

| | 04-real | 05-walkthrough（本目录） |
|---|---|---|
| 内容 | 真实用过的材料 | 虚构的完整演示 |
| 有没有结果 | 有，通过或被退回 | 没有，是模拟 |
| 用途 | 证明什么写法在真实场景活下来 | 让人知道合格的产出长什么样 |
| 数据 | 脱敏后的真实数据 | 全部编造 |

两个都要有。只放真实的，新来的人看不到完整的样子；只放演示的，册子就没有可信度。

## 写新走查的规矩

三条，缺一条就别放进来。

**一、数字必须自洽。** 编数据最容易翻车的是数字之间对不上。完成率、返工率、平均周期这几个数，要能用同一个口径互相验算。读者里有人会算。

**二、卡点必须真实。** 「负责人待指定」「台账两条状态空着」这类瑕疵，比漂亮的流程更有说服力。全是顺利的走查，一看就是编的。

**三、公司名和人名必须虚构，且不与真实企业重名。** 用行业通用叫法加虚构字号，人名只写岗位（张经理、李工），不写全名。

## 一条提醒

走查的作用是**降低第一次的门槛**，不是替代真实产出。

看完走查，下一步应该是照着做一份自己的，然后放进 `04-real/`。停在看走查，等于看完菜谱就饱了。
