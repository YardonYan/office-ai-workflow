# 真实产出收录

这里放真实用过的东西，不是模板，不是范文。

前三个文件是「应该怎么写」，这一册是「实际写成了什么样」。两者差得远，差距本身就是最有用的信息。

## 收什么

| 收 | 不收 |
|---|---|
| 你实际交出去、并且有反馈的文档 | 没给人看过的草稿 |
| 脱敏后的完整版（可删节，但要标注删了什么） | 只留骨架的空壳 |
| 有结果的（通过、退回、被追问） | 没有下文的 |
| 自己写的 | 别处抄来、来源不明的 |
| 一段真实的失败尝试 | 只挑成功的 |

「有结果」这条最重要。没被检验过的文档只是练习，放进来会误导后来的人。

## 命名

```
YYYY-MM-DD-场景-结果.md
```

例：

```
2026-11-05-月度复盘-一次通过.md
2026-11-12-跨部门邮件-被退回重写.md
```

结果写在文件名里，是为了让人一眼看出这份是正例还是反例。反例往往更有价值。

## 必填的头部

每份文件开头必须写清五件事，缺一件就不收：

```markdown
> **来源**：本人实际使用（或：经作者授权）
> **时间**：2026-11-05
> **场景**：8 人团队月度复盘，供周会用
> **脱敏**：已去除客户名称、金额、同事姓名；删除原稿第三节
> **结果**：一次通过，会上只补充了一个数据
```

五条的作用：

| 字段 | 回答什么 |
|---|---|
| 来源 | 这是谁写的，能不能追到人 |
| 时间 | 什么条件下写出来的，会不会过时 |
| 场景 | 换到别的场景还成不成立 |
| 脱敏 | 删了什么，看的人知道信息不完整 |
| 结果 | 值不值得学 |

## 脱敏红线

以下内容一律不进来，删比改安全：

- 客户名称、联系方式、合同金额
- 同事的真实姓名，改成「项目经理 A」这种
- 公司内部系统名、内网地址、账号
- 未公开的经营数据（收入、成本、毛利）
- 领导的原话，尤其是批评性的

判断方法：这份东西如果被同事看到，你会不会不自在。会，就别放。

## 正文结构

不强制，但建议四段：

```
## 背景
什么情况下写的，给谁看，要解决什么

## 产出
原文或节选。长文可以只放关键部分，标注删了什么

## 反馈
对方的反应：通过、退回、追问了什么

## 复盘
哪里有效、哪里多余、下次改什么
```

第四段是这册的核心。只有产出没有复盘，等于存了个文件。

## 怎么提交

```
1. 复制 _template.md
2. 按命名规则改名
3. 填头部五个字段
4. 正文至少写清背景和复盘
5. 提 PR，说明这份能不能公开
```

不确定能不能公开的，宁可先不放。脱敏做过头只是信息少一点，脱敏不到位是事故。

## 一册可以有多少份

不设上限，但设下限：**少于五份的时候，这册的说服力不如那六篇范文。**

一份真实产出证明不了什么，五份以上才能看出「什么样的写法在真实场景里活下来」。
