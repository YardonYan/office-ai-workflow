# 六种文档的骨架

> **来源**：六种文档的段落结构归纳自公开写作方法论（金字塔原理、四段式汇报等）与多篇公开文章的共同做法，结构属行业共识。判据、常见错误为本仓自写。
> 完整出处与核验方式见 [`00-sources.md`](./00-sources.md)。

周报、月报、会议纪要、邮件、方案、复盘。每种给一份可套的骨架，加三条判据。

这些骨架来自公开的写作方法论，结构是通用的，措辞和例子是本仓自写。套的时候只换内容，不改骨架。

---

## 一、周报

四段，短比全重要。

```
【本周进展】三条，每条带结果或数字
【风险与阻塞】有就写，含应对；没有写「暂无」
【下周计划】三条，带时间点
【需要支持】需要谁、做什么、什么时候
```

判据：

- 每条进展能被核查（做了什么、到什么程度）
- 风险不藏，且写明已在做什么
- 不超过 400 字

常见错误：写成日程表（周一开会、周二写文档）。读者要的是结果，不是时间线。

---

## 二、月报

五段，比周报正式，要有判断。

```
【本月概述】两句话：围绕什么目标，整体到什么程度
【重点完成】三到五条，按重要性排，每条带结果
【数据与变化】关键指标、环比、与目标的差距
【问题与原因】卡点是什么、为什么、已在做什么
【下月安排】目标、重点任务、时间节点
```

判据：

- 概述能让没参与的人两分钟看懂
- 数据有口径，能复算
- 问题不是罗列，要带原因判断

周报记流水，月报给判断。这是两者最大的区别。

---

## 三、会议纪要

五段。前两段是背景，后三段才是价值。

```
一、基本信息：主题、时间、地点、主持、记录、参会、缺席
二、议程：这次讨论哪几项
三、讨论要点：按议程顺序，只记观点和分歧，不记过程
四、决议事项：定了什么，谁定的
五、待办清单：序号 | 任务 | 负责人 | 截止时间 | 备注
```

判据：

- 每条待办有名字和日期，缺一个就不合格
- 只记结论和分歧，争论过程不进纪要
- 会后当天发出去

常见错误：把纪要写成速记。逐字记录既没人看，也容易引战。

---

## 四、邮件

五段。主题行是唯一的广告位。

```
主题：【类型】核心事项 - 项目 - 时间要求
一、结论：第一句说要什么、什么时候要
二、背景：为什么现在提这件事，两三句
三、具体需求：清单、数量、标准
四、时间节点：什么时候要，晚了会怎样
五、致谢与联系人：有问题找谁
```

主题前缀的四种类型：`【需确认】`、`【同步】`、`【风险】`、`【催办】`。

判据：

- 只看第一段就知道要不要回、什么时候回
- 需求具体到能执行（不要写「尽快」）
- 附件在正文里被点名，不要只写「见附件」

5W2H 自查：谁、什么事、何时、何地、为什么、怎么做、多少。发出去之前过一遍，缺哪个补哪个。

## 五、方案

六段。逻辑链是「为什么 - 做什么 - 怎么做 - 花多少 - 有什么风险」。

```
一、背景与问题：现在哪里不行，用数据说
二、目标：量化，可验收
三、策略：怎么做，三到四条，不要全
四、执行计划：阶段 | 时间 | 任务 | 负责人 | 交付物
五、预算与收益：先讲收益再讲投入
六、风险与预案：风险 | 可能性 | 影响 | 应对
```

判据：

- 目标能验收（「提升知名度」不行，「三个月内新增 X」才行）
- 执行计划具体到人和时间
- 每个风险有对应措施，不是只列风险

常见错误：只写优点。读的人会自己找缺点，找到就不信你了。

## 六、复盘

三种方法按场景选。

### GRAI：项目级复盘，重归因

```
G 目标：当初定的是什么，分终极目标和阶段目标
R 结果：实际发生了什么，和目的一一对应
A 原因：主观原因（可控）与客观原因（不可控），以主观为主
I 规律：停止什么、继续什么、新增什么
```

### KPT：周期级复盘，重迭代

```
K 保持：哪些做法有效，继续
P 问题：哪里不顺，具体到场景
T 尝试：下一周期试什么，必须是小而具体的动作
```

KPT 适合周、双周这种短周期。Try 一次只定一两个，多了必落空。

### AAR：行动后复盘，重快速

```
一、预期发生什么
二、实际发生什么
三、差异在哪、为什么
四、下次怎么改
```

### 三条通用要求

**归因追到第三层。** 问三次为什么，才到得了根因。第一次的答案通常是表象。

**经验写成「如果…那么…」。** 把触发条件和动作绑在一起，比「要加强沟通」可执行得多。

```
如果项目周期超过一个月，那么中途必须安排一次进度回顾。
```

**行动项要能被下次复盘检查。** 谁负责、什么时候完成、怎么算完成，三样齐。

### 复盘的四个禁忌

| 禁忌 | 表现 | 后果 |
|---|---|---|
| 报喜不报忧 | 只写成绩，问题一笔带过 | 写一百份也长不了能力 |
| 追责不追因 | 聚焦「谁做错了」 | 下次没人敢说真话 |
| 归因到客观 | 全是市场、政策、供应商 | 可控的部分永远不改进 |
| 行动项不落地 | 写了「加强协作」 | 下次复盘还是同样的问题 |

## 七、通用四条铁律

六种文档都适用。

**一、结论先行。** 第一段说结论和请求，后面才是支撑。读者的时间是稀缺资源。

**二、数据说话。** 「很多」「一些」「明显提升」都不算数。有数字给数字，没数字给事实。

**三、问题带方案。** 只报问题是把负担转给对方。带一两个方案和一个倾向。

**四、闭环。** 每份文档结尾都要有下一步：谁、什么时候、做什么。
