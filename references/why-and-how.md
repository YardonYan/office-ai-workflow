# 别人是怎么搭流水线的

这一册整理外部做法，用来解释主册为什么这么设计。看完能自己改结构，而不是只会照抄七步。

## 一、四种常见流派

### 1. 提示词链（Prompt Chain）

把一件大任务切成一串小任务，每一步用专门的提示词，上一步的输出直接作为下一步的输入。

典型的七步：选题 → 大纲 → 分段展开 → 标题 → 润色。

每步只干一件事。选题阶段提示词要发散（给我十个方向），写作阶段要收敛（按这个框架展开）。一步到位做不到这种切换，因为一次只能有一种语气。

适用：内容生产这类有明显阶段性的任务。

### 2. 数字员工（多角色接力）

给每个环节配一个角色，每个角色有固定的职责和提示词。比如选题参谋、竞品分析员、素材管家、日报秘书。

关键设计是接力：前面的产出直接喂给后面。人只出现在两端——开头丢素材，结尾拍板。

适用：每天或每周重复、环节边界清楚的工作。

### 3. 任务编排（DAG / TaskFlow）

把任务写成有依赖关系的步骤图，每一步声明依赖谁、产出什么、存到哪个文件。

和前面两种的区别在于显式化：不靠对话上下文传递，靠文件传递。断在哪一步，就从那一步接着跑。

典型结构：

```
step1-搜集.md → step2-筛选.md → step3-分析.md → final-report.md
```

适用：步骤多、耗时长、中间可能中断的任务。

### 4. 模板加变量

把提示词固化成模板，每次只替换几个变量。模板里写死角色、读者、任务、要求、输出格式。

这是最轻的一种流水线，一条提示词就是一个工位。

适用：高频、结构稳定、每次只换素材的任务。

## 二、四种流派共有的三件事

不管哪种做法，能做成的都做了这三件事。缺一件就会退化成「偶尔好用」。

### 第一件：中间产物落成文件

只靠聊天上下文，断一次就全没了。落成文件之后，可以检查、可以复用、可以单独改。

实操要求：每步明确说「把结果写到 X 文件」，跑完检查文件真的存在。不要看流程状态显示成功就以为成了。

### 第二件：交接处设检查点

检查点不在开头，在产物出来之后。内容两条：事实对不对（来源、数字、口径），格式够不够用（能不能直接进下一步）。

不过关就停。带着问题往下走，最后一定要整体重来。

### 第三件：预判失败分支

写清楚什么情况下停下来、停下来之后做什么。常见的四种：输入缺失、来源冲突、口径不一致、产物不合格。

不写失败分支的技能，遇到脏数据就会硬编一个结果，比报错更危险。

## 三、一步到位为什么不行

症状很一致：输出看着完整，每段都像那么回事，但改不动。

原因有三层：

| 层 | 机制 | 表现 |
|---|---|---|
| 认知 | 一次要兼顾的维度太多，注意力被摊薄 | 每项都及格，没有一项到位 |
| 结构 | 只有一个成品，没有中间态 | 要改只能推翻重来 |
| 策略 | 全程一种语气 | 该发散的地方不够散，该收敛的地方不够紧 |

对应的解法就是拆分、留中间物、分步换策略。

## 四、拆分不是越细越好

拆过头比不拆更糟。三个信号说明拆多了：

- 两个相邻步骤之间没有真正的交接物，只是在换说法
- 合并之后提示词没有变长多少
- 检查点里有一半是「确认上一步做过」

判据是**决策点**，不是文件大小：每一步的输入、风险、完成标准是否真的不同。不同才拆，相同就并。

## 五、这套七步是怎么来的

把上面四种做法对齐到办公场景，得到的就是主册那七步。

| 七步 | 借了哪种做法 | 关键设计 |
|---|---|---|
| 查资料 | 提示词链的第一步 | 先限定范围和判断重点，避免抓一堆无关信息 |
| 读文件 | 数字员工里的提取岗 | 五要素提取，不复述全文 |
| 理流程 | 编排里的结构化产物 | 图比文字省认知，且能暴露遗漏的审核节点 |
| 做表格 | 模板加变量 | 先锁口径再算，公式必须写出来 |
| 写汇报 | 提示词链的收敛段 | 每页一个结论，材料服从结论 |

相邻两步之间都有实体交接物：简报、清单、流程图、统计表。这是它成立的前提，不是形式。

## 六、自己改结构时的三条约束

想按自己的场景改造，改可以，但这三条别动：

1. **相邻步骤必须有实体交接物。** 没有就不是流水线，是五个独立问题。
2. **口径只在做表格那一步锁一次。** 后面所有数字引用它，不许另算。
3. **最后一步一定是初稿。** 人工复核不是可选项，是流程的一部分。

其余的（步骤数、顺序、每步的具体模板）都可以按场景调整。`variants.md` 里有几种改好的版本可以参照。
