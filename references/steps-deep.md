# 五步的详细操作规程

主册给了顺序和原则，这一册给每步的输入、动作、产物定义、检查项和常见错误。做某一步卡住时翻对应一节。

---

## 第一步 查资料

### 输入

| 要准备的 | 说明 |
|---|---|
| 主题 | 一句话说清要查什么，越窄越好 |
| 时间范围 | 最近一周、本月、本季度。不设范围等于查不完 |
| 判断重点 | 这次最关心什么：政策变化、竞品动作、客户反馈 |
| 用途 | 这份简报给谁看、要支撑什么结论 |

### 动作

1. 先限定范围，再开始查。范围不清就先去问，别边查边想。
2. 只保留能追溯到来源的信息。转述的、听说的、没出处的，一律不进简报。
3. 每条信息标三样：说了什么、来自哪、跟这次任务什么关系。
4. 控制在三到五条。超过五条说明筛得不够。

### 产物定义

一页三列简报：

| 信息点 | 来源 | 与工作的关系 |
|---|---|---|
| 客户反馈集中在交付周期 | 10 月售后汇总 | 本月需重点跟进 |
| 行业新规 11 月生效 | 部门通知 | 现有流程要改一处 |

### 检查

- 每条都能点回原始出处
- 时间在设定范围内
- 结论能直接支撑一个判断，不是资讯罗列
- 没有混入与主题无关的内容

### 常见错误

| 错误 | 后果 | 改法 |
|---|---|---|
| 把网页内容整段粘贴 | 简报变成收藏夹，没人看 | 只留结论句，细节留在来源里 |
| 来源写「网上」 | 无法核实，等于没有来源 | 写到具体文件名、链接或通知编号 |
| 贪多 | 五条以上就没有重点 | 逼自己删到三条，删不掉的说明主题没想清 |
| 只查正面信息 | 汇报时被问住 | 主动找一条反例或风险，一起放进简报 |

### 失败处理

查不到东西，不要编。改成两句话：查了什么范围、没查到什么。然后说明需要谁提供什么材料。

## 第二步 读文件

### 输入

| 要准备的 | 说明 |
|---|---|
| 文件本身 | PDF、纪要、制度、复盘，越原始越好 |
| 阅读目的 | 是要提炼待办，还是要提炼结论，两者取法不同 |
| 已知背景 | 上一份简报，用来圈定读哪些段落 |

### 动作

1. 先看目录和标题，圈出与目的相关的段落，不必通读。
2. 按五要素提取：关键结论、待办事项、负责人、截止时间、原文依据。
3. 负责人和时间只写文件里明写的。没写的留空，标注「原文未指定」。
4. 一段话里有多个待办，拆成多条，不要合并。

### 产物定义

| 事项 | 负责人 | 时间 | 依据 |
|---|---|---|---|
| 补全材料清单 | 行政 | 10 月 28 日 | 会议纪要第三段 |
| 跟进客户反馈 | 原文未指定 | 本周内 | 反馈汇总 |

### 检查

- 每条都能回到原文某一段
- 负责人和时间没有编造
- 待办是动作，不是状态（「跟进」是动作，「关注中」不是）
- 没有把背景描述误当成待办

### 常见错误

| 错误 | 后果 | 改法 |
|---|---|---|
| 让 AI 写摘要 | 读完还是不知道要做什么 | 明确要求输出行动清单，不要摘要 |
| 补全缺失的负责人 | 派错活，得罪人 | 留空标注，让人补 |
| 一条记录里塞三件事 | 执行时漏掉两件 | 拆成三条，各自有负责人 |
| 忽略附件里的表格 | 关键数据在表里，正文没有 | 要求同时读表格，并注明来自哪张表 |

### 失败处理

文件读不出内容（扫描件、乱码、加密），直接说读不了，请对方提供可复制版本。不要根据文件名猜内容。

## 第三步 理流程

### 输入

| 要准备的 | 说明 |
|---|---|
| 行动清单 | 上一步的产物，提供步骤和责任人 |
| 现有流程 | 如果有制度文件或旧流程图，一并给 |
| 画图目的 | 是给人看顺序，还是给人看职责 |

### 动作

1. 先定图的类型。讲先后用流程图，讲分工用职责图，两者不要混在一张。
2. 列出所有动作，标出哪些是并行的、哪些必须串行。
3. 标出人工审核节点。凡是产出要对外、要花钱、要动权限的，前面必须有人工确认。
4. 标出交接点：谁交给谁、交什么、什么时候交。

### 产物定义

一张图，包含：步骤顺序、并行分支、责任角色、审核节点、交接物。

配套一句说明：这张图从哪开始、到哪结束、有几个审核点。

### 检查

- 并行的事没有被画成先后
- 每个对外输出前面都有人工审核
- 责任人和执行人不是同一个笼统的「团队」
- 箭头上的动作是动词，不是「处理」「跟进」这类含糊词

### 常见错误

| 错误 | 后果 | 改法 |
|---|---|---|
| 全是方框没有判断 | 看不出分支，执行时走错 | 有条件的步骤用菱形，写清判断依据 |
| 漏掉审核 | 错误直接对外 | 凡是对外/花钱/动权限，前置审核 |
| 层级混乱 | 图和文字对不上 | 先定三层：阶段、步骤、动作，不要越级 |
| 图太大 | 一页放不下，汇报时看不清 | 拆成主图和子图，主图只留五个节点以内 |

### 失败处理

流程本身不清楚（没人说得清现在怎么走的），先画现状图，标出「这里不确定」。不要凭空设计理想流程再假装是现状。

## 第四步 做表格

### 输入

| 要准备的 | 说明 |
|---|---|
| 台账或原始表 | 越原始越好，不要给已经汇总过的 |
| 统计口径 | 按什么分组、按什么算完成、时间怎么切 |
| 输出用途 | 进汇报、进系统、还是给人核对 |

### 动作

1. 先看字段。缺关键字段（状态、负责人、时间）就先补，补不了标注缺失。
2. 统一口径：什么叫完成、什么叫进行中、跨月任务算哪个月。写下来。
3. 再汇总。顺序不能反，先算后定义口径一定会返工。
4. 把公式写出来，例如：完成率 = 已完成 ÷ 总数。让人能复核。

### 产物定义

一张统计表，至少含：分类、数量、占比、口径说明。

| 状态 | 数量 | 占比 |
|---|---|---|
| 已完成 | 18 | 60% |
| 进行中 | 9 | 30% |
| 待处理 | 3 | 10% |

口径：完成率 = 已完成 ÷ 总数 = 18 ÷ 30 = 60%；统计区间 10 月 1 日至 31 日。

### 检查

- 字段口径全程一致，没有中途换定义
- 空值没有被当成 0
- 公式能复算，结果对得上
- 图表和表格数字一致
- 分类加起来等于总数

### 常见错误

| 错误 | 后果 | 改法 |
|---|---|---|
| 空值当 0 | 完成率虚低或虚高 | 空值单列「未填」，不计入分母 |
| 跨月任务重复计 | 总数虚高 | 明确归属规则，只计一次 |
| 图表单独算一遍 | 图和表对不上 | 图表只读表里的数，不另算 |
| 只给结果不给公式 | 没人敢用 | 公式写在表下方一行 |

### 失败处理

数据本身矛盾（同一任务两个状态），不要自己选一个。列出来，标明冲突，请业务方判定。

## 第五步 写汇报

### 输入

| 要准备的 | 说明 |
|---|---|
| 前三步的产物 | 简报、清单、统计表，缺一样都会导致某页空 |
| 汇报对象 | 直属上级、跨级高管、平级、客户，深度不同 |
| 时长 | 五分钟和三十分钟，页数差一倍 |

### 动作

1. 先定结论。这次汇报要对方知道什么、决定什么。结论定不下来，先别做页面。
2. 按结论选材料。跟结论无关的，再好看也删掉。
3. 五页骨架：目标、进展、数据、问题、计划。可按场景增减，但顺序不乱。
4. 每页写结论式标题，不写主题词。
5. 数字全部引自统计表，不重算。

### 产物定义

一份大纲，每页含：结论式标题、三个以内的要点、数据来源标注。

```
P1 本月目标：完成 X 系统一期上线
P2 进展：三个模块已交付，一个在联调
P3 数据：完成率 60%，较上月提升 15 个百分点（来源：统计表）
P4 问题：接口文档延迟，已启用备用方案
P5 下月：联调收尾、压测、提测
```

### 检查

- 每页只有一个结论
- 标题是结论句，不是「工作进展」这类主题词
- 数字与统计表一致
- 有问题页，且带应对
- 最后一页有明确的下一步或请求

### 常见错误

| 错误 | 后果 | 改法 |
|---|---|---|
| 先排版后想结论 | 页面漂亮但说服不了人 | 先用一句话写结论，再决定放什么 |
| 每页塞五个要点 | 一个都记不住 | 一页一个观点，多的拆页 |
| 只报喜 | 领导现场问住 | 主动留一页问题与应对 |
| 数字临时重算 | 与统计表冲突 | 一律引用，不重算 |

### 失败处理

材料不够支撑结论，两条路：缩小结论范围，或者退回补材料。不要靠措辞把弱证据说成强结论。
