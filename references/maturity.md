# 成熟度与治理

前面几册讲怎么把一件事做成流程。这一册讲两件更实际的事：**这条流程现在处在什么水平**，以及**怎么保证它不出事**。

## 一、四个成熟度

| 级别 | 叫什么 | 特征 | 典型表现 |
|---|---|---|---|
| L1 | 辅助生成 | 人做主体，AI 出草稿 | 你写提纲，AI 补内容；你审一遍再改 |
| L2 | 受控自动化 | 固定步骤，固定产出 | 七步流水线，每步有检查清单，人只核对 |
| L3 | 自主执行 | 有触发信号，能自己跑完全程 | 到时间自动启动，异常才找人 |
| L4 | 自优化 | 会自己发现问题并调整步骤 | 连续三次某步没查出问题，自动提议删掉 |

多数办公场景做到 L2 就够了，收益最大的是 L1 到 L2。L3 只在真的高频时才划算，L4 属于长期目标。

判断自己在哪一级，看一个问题：**这条流程不启动，是因为你没开口，还是因为它没被触发？** 前者是 L1-L2，后者是 L3。

## 二、升级的路

从 L2 往上走，缺的通常不是工具，是三样东西：

| 缺什么 | 具体表现 | 补法 |
|---|---|---|
| 触发信号 | 每次都要人想起来 | 定三个：定时、事件、阈值 |
| 判断依据 | AI 跑完不知道对不对 | 每步的完成标准要能判断是或否 |
| 异常出口 | 出错了没人知道 | 写明什么情况下停下来找人 |

三样齐了才叫 L3。缺一样，就还是 L2。

## 三、治理四问

流程跑起来之后，真正难的是可控。四个问题，答不上来就别扩规模。

| 问题 | 具体 | 办公场景的答案 |
|---|---|---|
| 谁开通 | 谁能用这条流程、能用到什么程度 | 哪些同事可以自己跑，哪些要你带着跑 |
| 谁隔离 | 不同人的数据怎么不串 | 每个项目的材料放各自目录，不混用 |
| 越界谁知 | 出了范围谁先知道 | 数字对不上、口径变了，谁第一时间发现 |
| 验收谁签 | 谁对最终交付负责 | 复核那一步必须有人签字，不能是 AI 自己说可以 |

第四问最容易被跳过。**AI 说「已完成」不算完成，得有人核对过才算。**

## 四、从「成功一次」到「成功率」

单次成功没有意义，要看连续表现。

三个指标比「效果不错」有用得多：

| 指标 | 怎么记 | 说明什么 |
|---|---|---|
| 连续成功率 | 十次里有几次一次通过 | 稳定性 |
| 失败原因分类 | 材料缺 / 口径错 / 判断偏 | 该补哪一环 |
| 人工接管时间 | 每次要花多久改 | 到底省了多少 |

只记第一个会漏掉关键信息。连续十次都过，但每次要花两小时改，等于没省。

## 五、术语对齐

同一个词各说各话，是协作里最常见的内耗。

| 词 | 本仓的定义 | 容易混的用法 |
|---|---|---|
| 工作流 | 有固定步骤、固定产物、可重复执行的一串动作 | 泛指「用 AI 干活」 |
| 步骤 | 有明确输入输出的一环 | 泛指「大概做一下」 |
| 交接物 | 上一步产出、下一步消费的实体 | 泛指「结果」 |
| 产物契约 | 事先定死的结构、字段、完成标准 | 泛指「要求」 |
| 复核 | 交付前抽查三处数字与口径 | 泛指「看一眼」 |

用词统一，讨论才在同一个平面上。

## 六、别把演示当成果

一个常见的错觉：演示跑通了，就以为能用了。

演示只需要成功一次，生产需要连续成功。两者的差距在边界情况——材料不全、口径冲突、多人同时改。

判断方法：**拿三份真实的、不完美的材料跑一遍。** 能过，才算能进日常；过不了，说明还停在演示阶段。

## 七、什么时候该停

不是所有流程都值得往上升级。

| 信号 | 说明 |
|---|---|
| 一个月用不到两次 | 停在 L1，手工做 |
| 每次的材料差异极大 | 很难固定步骤，停在 L2 上半 |
| 出错代价不可承受 | 加人工复核，别追求自动化 |
| 维护成本超过手工成本 | 降级或废掉 |

流程是手段。它存在的意义是让人省事，不是让人伺候它。
