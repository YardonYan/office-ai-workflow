# 把工作流写成别人能用的文档

会做不会写，等于只有自己能用。这一册讲怎么写，参照的是开源社区里被验证过的那套写法。

## 一、先想清楚给谁看

| 读者 | 他想知道什么 | 你该重点写 |
|---|---|---|
| 完全新手 | 这东西能帮我干什么 | 一个具体场景 + 三十秒上手 |
| 有类似需求的人 | 它和我的场景差多远 | 适用范围与边界 |
| 想改造的人 | 结构为什么这么设计 | 交接物、契约、为什么这么拆 |
| 想贡献的人 | 我能加什么、按什么标准 | 格式要求与验收标准 |

一份文档不可能同时讨好四种人。通常是：开头照顾第一种，中间照顾第二三种，末尾照顾第四种。

## 二、八段结构

这套结构来自社区里被反复使用的 Prompt README 模式，几乎适合所有工作流文档。

### 1. 用途

两句话：做什么，**明确不做什么**。

```
这个工作流把客户反馈整理成可派活的清单。
它不做需求优先级判断，那需要产品参与。
```

「不做什么」这一句最容易被省略，也最容易被误用。省了它，用户会拿它干别的，然后回来怪你没说清。

### 2. 什么时候用

写信号，不写好处。

| 不合格 | 合格 |
|---|---|
| 提升办公效率 | 每周要交周报，手上有零散记录 |
| 适用于各种场景 | 材料散在三个以上文件里，且要给别人看 |

判断方法：读者能不能对着这一条说「对，我现在就是这个情况」。

### 3. 输入

表格形式，四列：字段、必填与否、默认值、什么算坏输入。

第四列是关键。只列出「需要主题」，用户会给你一个「行业动态」；写上「主题太宽，收窄到一个具体问题」，他就知道该怎么给。

### 4. 输出契约

写死产物长什么样。三样要齐：结构、必需字段、完成标准。

```
输出一张三列表：信息点 | 来源 | 与工作的关系
最多四行
每行的来源必须能打开
```

契约写不清，用户拿到的结果每次都不一样，然后归因于「AI 不稳定」。

### 5. 护栏

三件事：什么时候该反问、什么该拒绝、隐私怎么处理。

```
如果输入缺负责人，标「待指定」，不要推测。
如果两份材料数字冲突，都列出来，不要替用户选。
不要把公司内部数据写进输出。
```

护栏的作用不是限制，是让输出可预期。

### 6. 示例

一条正例，一条边界用例。只给正例，用户不知道边界在哪。

正例展示「好的长什么样」，边界用例展示「输入不完整时该怎么处理」。

示例要能看出判断标准，不是只看格式。比如：

| 弱示例 | 强示例 |
|---|---|
| 输出一份有用的评审意见 | 发现：严重度高；文件在 src/billing；问题是退款行在比对前被过滤，负向调整消失；证据是查询条件加了 amount > 0，但测试夹具里有退款行 |

强示例教的是标准，弱示例只教了排版。

### 7. 运行说明

怎么跑、产物存哪。

最简单的写法是一段可复制的提示词，加一句「把结果存到 `output/日期-主题.md`」。

不写产物位置的后果是：每个人存的地方都不一样，第二周就找不到了。

### 8. 变更记录

改过什么、为什么改。

不用长，一行一条。没有变更记录的文档，用户不知道自己在用的是哪一版。

## 三、三种文档形态

| 形态 | 适合 | 特点 |
|---|---|---|
| Prompt README | 单个提示词或单步流程 | 一个文件说清全部，最轻 |
| 模板文件 | 多步流程的每一环 | 每个文件独立可用，可自由组合 |
| 案例库 | 有多个真实应用的成熟流程 | 靠实例说服，适合推广 |

多数项目是两种混用：README 讲整体，templates 给可复制的东西，examples 做示范。

## 四、第一屏决定成败

别人打开你的仓库，前十秒决定他会不会继续看。第一屏该有什么：

| 位置 | 放什么 |
|---|---|
| 标题下第一行 | 一句话说清这东西干什么 |
| 一张图 | 流程或效果，让人三秒理解结构 |
| 三个数字或标签 | 几步、耗时、依赖 |
| 一个可复制的入口 | 最快的上手方式 |

不放：项目背景故事、致谢、目录树。

## 五、让人真的用起来

写了文档没人用，通常是三个原因：

| 原因 | 表现 | 解法 |
|---|---|---|
| 门槛太高 | 要先读五千字才能开始 | 给一条能立刻复制的提示词 |
| 不知道用在哪 | 全是抽象描述 | 开头放一个具体场景 |
| 怕用错 | 没写边界 | 明写不适用范围 |

第一条最致命。做得好的项目都有一个「三十秒上手」区块：一段话，复制，粘贴，出结果。

## 六、维护

| 什么时候改 | 改什么 |
|---|---|
| 加了一步 | 更新流程图、目录、变更记录 |
| 改了提示词 | 更新模板、补一条变更记录，说明为什么 |
| 发现不适用的场景 | 补进「什么时候不该用」 |
| 有人问了三遍同一个问题 | 说明文档没写清，补进正文 |

最后一条最有用。同一个问题被问三次，不是用户不看文档，是文档没说清。

## 七、一份合格文档的自检

发出去之前过一遍：

- [ ] 第一屏能让人知道这东西干什么
- [ ] 有一个三十秒能跑通的入口
- [ ] 写了不做什么
- [ ] 输入表里有「什么算坏输入」
- [ ] 输出契约能判断对错
- [ ] 有一正例一边界用例
- [ ] 写了不适用范围
- [ ] 有变更记录

八条里缺三条以上，别人用起来一定会有问题。
