# 五种思考方式

写流程、做汇报、审方案的时候，最有效的一招不是把步骤写得更细，是换一种提问方式。

下面五种都是成熟的方法论，模型和人都学过。你不需要解释它是什么，只要说「用这种方式看一遍」，输出就会变。

## 一、第一性原理

**什么时候用**：怀疑「这个任务本身是不是就问错了」。

**怎么问**：

```
不要沿着现有方案继续优化。从第一性原理重新问：这件事到底要解决什么，
最小必要的做法是什么。
```

**办公场景**：

领导让你「把周报写得更详细」，直接照做会越写越长。用第一性原理问一句：他为什么觉得不够？可能是想知道风险，而风险只用三行就说完。那问题不是详细度，是信息结构。

**产出**：把「要做得更好」换回「要解决什么」，通常会发现原需求可以更小。

## 二、对抗性审查

**什么时候用**：方案定稿前、汇报交出去前、流程设计完。

**怎么问**：

```
对这个方案做一次对抗性审查。不要帮我找理由，优先找能推翻核心假设的反例。
```

**办公场景**：

方案写的是「加两道确认节点降低返工率」。普通问法是「有没有问题」，模型会告诉你「要注意执行力度」。对抗性问法会追问：返工真的是因为没确认吗？还是范围本身没定清？加了两道确认，客户会不会直接绕过流程找你口头改？

**产出**：三到五条真正的风险，而不是三到五句「需注意」。

## 三、消融实验

**什么时候用**：一次做了好几个改动，想知道哪个真的有用。

**怎么问**：

```
给这几个改动设计消融实验，判断收益到底来自哪一个。
```

**办公场景**：

「加了模板、加了检查清单、改了口径定义」之后返工率降了。别急着归功于三件事。分别去掉一个试试：只留模板，返工率是多少？可能单靠口径定义就解决了七成，另外两样是心理安慰。

**产出**：知道哪一步该留、哪一步是摆设。这是「流程做减法」的依据。

## 四、奥卡姆剃刀

**什么时候用**：流程越加越长，步骤越写越多。

**怎么问**：

```
用奥卡姆剃刀审查这条流程，在满足需求的前提下删掉所有非必要的步骤。
```

**办公场景**：

一条七步流程里，第 3 步和第 4 步的产物是同一张表，只是叫法不同。剃刀会告诉你：合并。判断标准是「去掉这一步，最终产出会不会变差」——不变差就是多余的。

**产出**：步骤数减下来，每步的分量变重。

## 五、边界检查

**什么时候用**：文档结构乱、职责不清、一件事牵扯太多人。

**怎么问**：

```
按高内聚低耦合的原则检查这份材料的职责边界。哪几块其实该拆成两份文档？
不要为了拆而拆。
```

**办公场景**：

一份复盘里同时写了业务进展、技术方案、人员安排。读者是三拨人，各自只关心一块。边界检查会告诉你：拆成三份，各给各的。

**产出**：结构清楚，读者不用在无关内容里找自己那段。

## 把这五种连起来用

模型能力够的时候，五种串起来是一句话：

```
从第一性原理重新分析这个问题，对方案做对抗性审查；
核心改动必须能用消融实验证明有效；设计遵循奥卡姆剃刀；
文档结构做一次边界检查。
```

这几句背后是五个认知动作：**重新定义问题 → 攻击假设 → 验证贡献 → 删除复杂度 → 整理边界**。

## 和七步的关系

七步管「按什么顺序做」，这一册管「用什么方式想」。

两者不冲突：

| 场景 | 用哪个 |
|---|---|
| 任务清楚，只是要按步骤推进 | 七步 |
| 任务本身可疑，或做完不确定对不对 | 五种思考方式 |
| 两个都用 | 先用思考方式定方向，再用七步执行 |

## 一条提醒

这五种不是万能钥匙。它们的作用是**把模糊的判断变成可回答的问题**，不是替你做判断。

用了之后，结论还是要自己下。工具负责把问题问对，人负责回答。

## 定期重估

方法本身也会过时。

半年前有用的步骤，可能是在补当时模型或工具的短板。工具变了，这些步骤就从「保障」变成了「噪声」。

判断方法：某个步骤连续三次都没查出问题，就试着跳过一次。跳过之后结果没变差，它就是可以删的。

流程是手段，不是纪律。
